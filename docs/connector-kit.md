# BotBusConnectorKit

公开仓库 `botbus-io/botbus-protocol` 的 `Sources/BotBusConnectorKit`。连接器契约、`TaskStore`、`CommandDispatcher` 与连接器共用的本机基础设施；按 app 仓库的开源连接器设计稿（`docs/superpowers/specs/2026-09-27-open-connectors-design.md`） 第二步起随公开仓库 `botbus-io/botbus-protocol` 发布。只依赖 `BotBusProtocol` 与公开的 `BotBusConnectorParsers`；**不能** import `BotBusAgentCore` 或 `BotBusConnectors`，凡是要碰 Relay、凭据、产物上传、预览、远程操作的都留在 AgentCore，分发器对它们只认 `DispatcherServices.swift` 里的协议。以下源码均在 `Sources/BotBusConnectorKit/`。

## 逐层定位

| 层 | 文件 | 职责 |
|---|---|---|
| 状态入口 | `TaskStore.swift`、`ArtifactArchive.swift`、`OutsideProjectRule.swift`、`WorktreeResolver.swift` | actor，任务对账、实时所有权、项目合并、通知与事件流；按任务挂产物（`Task.artifacts`）并持久化到 `artifacts.json`；按本机规则判定「不在项目中」（`Task.outsideProject`）；把 git worktree 里的会话归到主仓库（`Task.worktreePath`，对应关系记在 `worktrees.json`） |
| 手机发起的会话 | `PhoneTaskArchive.swift`、`TaskStore.swift`（`DesktopResume.swift` 在 BotBusConnectors） | Mac 菜单的 Agent 详情用，不进协议：`TaskStore.apply` 见到 `origin == .watch` 就记下 id（`phone-tasks.json`，≤ 500 条），`phoneStartedTasks()` 按 updatedAt 降序给出仍可见的那些；**不改写** `origin`——连接器靠 `.desktop` 判断"电脑上正开着、不是我们的进程"。`DesktopResume` 按来源拼在终端里接上会话的命令（`claude --resume`、`codex resume`、`hermes --resume`、`pi --session <文件>`、`openclaw tui --session`；ACP 与 DeepSeek Harness 返回 nil——dsh 网页端没有按会话的地址、随包 profile 里没有交互终端），工作目录取 `workingDirectory`；Hermes / Pi / OpenClaw 只给这一条命令把 CLI 所在目录放到 PATH 最前（`AgentBinary.pathDirectories`，与连接器同一套），免得用户 shell 里的旧 node 跑不动脚本 |
| 后端发现 | `ConnectorRegistry.swift`、`AgentIdentity.swift` | 探测可用性、开关、健康信息与电脑身份 |
| 命令入口 | `CommandDispatcher.swift`、`DispatcherServices.swift`、`TaskConnector.swift` | 目标校验、并发去重、按来源执行、结果与所有权交接；分发器依赖的五项本机服务（对话图片上传、手机发图下载、按需取回、未提交改动、远程操作）只以 `DispatcherServices.swift` 里的协议出现，实现在 AgentCore 注入 |
| 失败后系统授权诊断 | `SystemPermissionInspection.swift`、`TaskStore.swift`、`CommandDispatcher.swift` | app 注入 `SystemPermissionInspector`，只在任务新进入失败或 start/followUp 命令失败之后检查；Core 不调用 AX、不申请权限、不操作弹窗；结果与原错误并存 |
| 2.5 来源公共 | `AgentPaths.swift`、`SessionObserver.swift` | Hermes / Pi / OpenClaw 的目录与可执行文件探测（`AgentBinary.environment` 给 node 脚本补 PATH）；Pi 与 Hermes 共用的轮询对账 |
| 本机 HTTP | `LocalHookServer.swift`、`OneShotContinuation.swift` | 回环监听、挂起审批、超时/断开的一次性完成；端口文件名与解析层错误格式可配置 |
| agent 工具 | `TaskContextRegistry.swift`、`AgentTools.swift`（服务端 `LocalToolAPI.swift` 在 AgentCore） | 手机任务的 task token（签发/绑定/等待解析）；注入配置、说明文字、Claude 参数与 Codex `config`；本机工具 API 的路由与 JSON 契约（`botbus` CLI / MCP 的服务端） |
| 对话读取 | `MessageReader.swift`、`TranscriptEntry.swift`（`CodexMessageReader.swift` / `ClaudeMessageReader.swift` 在 BotBusConnectors） | Codex SQLite / Claude transcript（Hermes / Pi / OpenClaw 的读取器在各自一行），只读且独立于控制连接器；产出 `TranscriptEntry`（消息 + 用户发的图、Codex 生成图的来源 + Agent 回复里的路径候选），纯图片消息 `text` 为空串也保留 |
| 回复里的文件 | `TranscriptFileRefs.swift` | 协议 2.9 `Message.files`：`candidates(in:)` 从 Agent 回复的**未截断**原文里认媒体路径（反引号、Markdown 链接目标含 `<…>`、裸路径；只认图片 / 视频 / PDF 扩展名，不认 URL；每条最多 32 个），在公共 `transcriptEntry` 里只给 `.agent` 填（Claude / Pi 整份解析再截尾，只给最终窗口里的回复认）；`resolve` / `validate` 按任务项目目录做 realpath 校验，分发器补卡片与 `fetchFile` 复核共用 |
| 网络抽象 | `WebSocketTransport.swift`、`URLSessionWebSocketTransport.swift` | 可替换 transport、握手、关闭码、ping |
| 小工具 | `MediaType.swift`、`StringExtensions.swift`、`Reexports.swift` | 按扩展名定 MIME（产物上传与文件卡片共用）；`String.trimmed`；`@_exported import BotBusConnectorParsers`，让依赖 Kit 的包直接拿到 `JSONValue`、`StreamJSONReader` 与 Codex 帧类型（公开仓库 v0.2.0 并入后删除） |

`ConnectorRegistry()` 不传描述符时用 `ConnectorDescriptor.placeholders()`：每个一档 kind 一条、视为已装已启用、不探测本机，给测试与不探测的调用方用；app 一律传 BotBusConnectors 的 `ConnectorDescriptor.all(...)`。

## 必须保留的行为

- `TaskStore` 是任务写入中枢；`.live` 优先于 `.observer`。`releaseLive` 后有 30 秒交接宽限，防止数据库落盘滞后使任务消失。
- `TaskStore.events()` 只允许一个订阅者，新订阅接管旧流。不要为菜单计数另建事件订阅；通过 store 查询。
- 首次 reconcile 建立静默基线；通知按状态与请求 ID 去重。项目或连接器信息变化要发全量 snapshot，因为没有项目增量事件。
- `CommandDispatcher` 按命令 ID 记住执行中的 Task 和完成结果；重复请求等待/复用同一次执行。清理去重表时不能淘汰执行中的条目。
- 系统授权诊断由 app 给 `TaskStore` 与 `CommandDispatcher` 注入同一个 `SystemPermissionInspector`（截图已上传才带 `Artifact`）；默认十秒后回 nil，不因检查卡住失败回执。`TaskStore` 只在非静默的新失败状态异步扫描，不新增事件订阅；`systemPermission` 单独存在内存，在 `stamped()` 合并，连接器刷新不得清掉。重试离开失败、移除、换 agentId 或 `setSystemPermissionInspector` 会清空提示并作废在途结果。额外通知按 notice.id 全局去重十分钟、最多记 200 个；原始 status/error/lastMessage 不改，也不把弹窗认定为失败原因。`CommandDispatcher` 只为 startTask/followUp 失败补 notice（新建尚无 taskId 也可），读操作、审批、中断、错误目标与取消不检查；同 command.id 复用同一检查结果。app 解除配对、关闭诊断或退出时必须对两者调用 `setSystemPermissionInspector(nil)`。
- `fetchMessages` 走 `MessageReader`，不认领实时所有权、不改任务状态；不要要求控制子进程先启动。消息过滤保持 `reasoning` 不进入对话。`limit` 只数对话（`role != .tool`），窗口一律走 `TranscriptWindow.latest`：最近 `limit` 条对话加夹在其间的工具行，工具行另有 `maxToolMessages` 上限、超了丢最旧的；SQL 读取器（Codex、Hermes）倒着翻页直到 `TranscriptWindow.isEnough`，OpenClaw 按 `recordLimit(forConversation:)` 多要记录。工具行正文截到 `maxToolTextLength`（200 字）；Claude 的 `tool_use` 各出一行 `.tool`（id `<uuid>#n`），不并进 Agent 正文。有图没传好时先发文字、回执不等上传，后台传完重读再发一次；一次 `fetchMessages` 最多补发一次，补发前再查连接器开关。补全之后丢掉「没字（去掉空白）、没 `attachments`、没 `files`、也没有图在排队」的消息（图已删、解不出、没有上传器），`MessageAttachmentUploader.resolve` 的 `pending` 按条标出还在排队的；仍在排队的空消息照发，手机画「图片」占位。
- `fetchChanges`（协议 2.11）是手机读 Mac 项目内容的第二个入口，同样只读：store 里必须有这个任务、来源已启用、不是「不在项目中」；目录取 `TaskRecord.workingDirectory`（worktree 优先），经 `TranscriptFileRefs.projectRoot` 同一套过宽目录规则挡掉 home、`/Users` 等；范围限定在这个目录（`--relative`、`ls-files -- .`），软链接不跟随，仓库配置不能让 git 执行命令（`WorkingChangesReaderTests` 有 fsmonitor 用例）。产物 id 随 `CommandResult.artifactId` 返回，不进 `Task.artifacts`，不认领所有权。
- `fetchFile` 是手机按路径读 Mac 文件的唯一入口，规则不能放松：① 前置校验与 `fetchMessages` 相同（来源、读取器、连接器启用）；② store 里必须有这个任务（取它的 `projectPath`，没有就失败，不拿别的目录兜底）；③ 重读对话，`messageId` 必须是 `role == .agent` 的消息，`path` 必须与它**此刻** `TranscriptFileRefs.resolve` 结果里的某个 `path` 完全相等，否则「这个文件不在对话里」；④ 上传前再 `validate` 一次且真实路径不变。`TranscriptFileRefs` 的规则：项目根 realpath 后若等于或是当前 home、`broadRoots`（`/`、`/Users`、`/System/Volumes/Data` 一组、`/Volumes`、`/private/var`、`/tmp`、`/Library`、`/Applications`、`/opt`、`/usr` 等）任一路径的祖先，整个任务不出卡片、`fetchFile` 失败（只拦本身与祖先，不拦后代：home 下的子目录、`/private/var/folders` 的临时目录照常可用，判定是纯函数 `isAcceptableProjectRoot`）；realpath 后必须在项目目录内（按路径组件比，`/proj` 不匹配 `/proj2`）、项目根以下任一段以 `.` 开头都拒（项目本身在点目录下不算）、真实文件的扩展名是媒体类型、必须是普通文件、每条最多 4 个、按真实路径去重，`~user` 不展开。⑤ 图片与 PDF 按 fd 读（`FileFetchService.readVerified`）：`O_NOFOLLOW | O_NONBLOCK` 打开、`fstat` 须是普通文件、`F_GETPATH` 须与校验过的真实路径逐字相等，之后只从这个 fd 读；硬链接不拒（`F_GETPATH` 偶尔报成另一个名字时误拒，重试即可）。视频交给 AVFoundation 只能按路径读，校验到读取之间的空当是接受的残余风险（要在本机有写权限并抢时间，能做到的 Agent 本来就能 cp）。成功时先发带 `artifactId` 的 `taskMessages` 再回执；不认领所有权、不改任务状态、不进 `Task.artifacts`。`messageId` 只在最近 40 条对话里找。`fetchMessages` 的卡片同样只在 store 里有任务时才出。
- 产物由 `TaskStore` 单独按任务记（新的在前、≤ 10、≤ 200 个任务），在 `stamped()` 里合并进外发的 `TaskRecord`；连接器与观察者不感知产物，它们的 upsert / reconcile 不会覆盖。没有产物时 `artifacts` 必须是 nil（协议要求省略键，Relay 拒收超过 10 个的帧）。同任务同端口/目录重新分享预览时替换旧条目，`ArtifactChange.displaced` 里的预览由调用方去停。预览不跨重启（加载时丢弃），过期产物在加载、`snapshot()` 与定时 `pruneExpiredArtifacts()` 时摘掉。
- 「不在项目中」（协议 2.6）同产物一样在 `stamped()` 里打到外发任务上，只写 true 或 nil；规则只认固定位置（空路径、`/`、`/tmp`、主目录本身、主目录下 `Desktop` / `Downloads` / `Documents` 本身、各 Agent 的默认工作区），不看有没有 `.git`，这些目录的子目录照常算项目。它们也不进 `mergedProjects()`。OpenClaw 读配置时用 `setAgentWorkspace` 报工作区，变了就补全量快照。空 `startTask.projectPath` 由 `CommandDispatcher` 换成 `TaskStore.homeDirectory`，OpenClaw 例外（它自己退回默认工作区）。`startTask.newProject` 由 `CommandDispatcher` 在 `TaskStore.projectsRoot` 下建子文件夹再启动：名字按 `Command.StartTask.isValidNewProjectName` 校验、再核一遍必须是存放目录的直接子目录；同名已存在就拒绝、不复用；先确认连接器可用再建目录。存放目录本身也算「不在项目中」。
- worktree（协议 2.7）同样在 `stamped()` 里改写：工作目录取 `worktreePath ?? projectPath`（盖两次结果不变），`WorktreeResolver` 认出主仓库就把 `projectPath` / `projectName` 换成主仓库、真实目录放进 `worktreePath`；`outsideProject` 按主仓库判。连接器报的项目也换成主仓库，`mergedProjects()` 去重。连接器与观察者只记真实 cwd——续聊、预览回退目录（`LocalToolAPI` 读 `workingDirectory`）都用它，本机代码不要把外发任务的 `projectPath` 当执行目录。`WorktreeResolver` 尽量不读盘：`<仓库>/.claude/worktrees/<名字>` 按路径归；只有路径里有一层 `worktrees` 目录时才往上（不越过那层）找 `.git` 文件，按 `gitdir:` 路径的形状取主仓库，不读主仓库里的文件——项目多在「文稿」「桌面」，碰一下就会弹系统授权。已删掉又没记过的 worktree（目录不在了）按同名退回：见过的主仓库与普通项目里恰好一个同名就归过去，多个不猜；这是推断，不进缓存不落盘。`performReconcile` 先给项目盖章再给任务盖章，好让同一轮报上来的主仓库先被见到。worktree 已删的会话 `followUp` 由 `CommandDispatcher` 直接回失败，不退回主仓库。
